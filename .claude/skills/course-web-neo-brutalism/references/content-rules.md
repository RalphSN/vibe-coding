# 內容規範

## 1. 每個單元的結構

依序呈現，讀者每次都知道下一段是什麼：

1. 頂部資訊列：`模組 2 ／ 單元 3 of 6` ＋ 進度條 ＋ 閱讀時間（中文每分鐘 300 字）
2. 這課學到的 3 件事：剛好 3 條，一句一條
3. 比喻 ＋ 比喻的限制：兩張卡片並排或錯開
4. 心智模型：一張 SVG 圖 ＋ 一句圖說
5. 正式定義：1–3 個術語，中英並列，自動加入術語表
6. 詳細說明：完整解說的範例、壞 → 好的對照、表格、圖、互動，最後至少一段「深入：」標題的段落
7. 常見錯誤：剛好 3 個，「錯誤 → 為什麼錯 → 正確」
8. 深入思考（選用）：最多 2 題開放題，答案藏在 `<details>`
9. 三個重點：剛好 3 條
10. 頁尾：來源連結、查證日期、「標記為已完成」、上一課／下一課

- 不放選擇題、暖身回顧、補完題、預測題、分類練習、總複習測驗（2026-10-29 起）。
- 單元長度：預設 8–15 分鐘；內容不夠時加「深入」段落，不加題目。
- 每課只教一個核心概念；段落最多 3 句。
- 情境要多樣：職場、程式、生活各至少出現一次。

## 2. 深入段落與深入思考題

### 2.1 深入段落

`examples.blocks` 最後至少一個 `{ type: 'heading', id, text: '深入：…' }`，後面接 1–3 段文字、表格或清單。寫這些：

- 原理：為什麼會這樣運作，而不只是怎麼用。
- 邊界：什麼時候不適用、會在哪裡壞掉、有哪些例外。
- 取捨：兩種做法各自的代價，實務上怎麼選。
- 現況：版本、法規、數字的最新狀態與出處（第 4 節）。

### 2.2 深入思考題（選用）

```js
practice: [
  { level: '深入思考', type: 'reveal', q: ['題目（一個新情境）'], answer: ['推理過程', '結論與常見的錯誤想法'] },
],
```

- 每課最多 2 題；沒有夠深的題目就整個不放。
- 只收要多步推理、或把概念遷移到新情境才答得出來的題目。看完課文就能直接找到答案的，不算。
- 不用選擇題（`type: 'mc'`）。

### 2.3 原本會出題的內容怎麼處理

| 原本 | 改成 |
|---|---|
| 分類練習（`classify`） | `table` 區塊：項目、分類、為什麼 |
| 預測輸出（`predict`） | 可執行的範例直接顯示結果，解說寫在下方 |
| 補完題（`tryit`） | 完整解說的範例 |
| 選擇題的解析 | 有價值的「為什麼」併進常見錯誤或深入段落 |
| 總複習測驗 | 一頁地圖：全書架構、每部最重要的行動、會過時的內容 |

## 3. 視覺化

能畫就畫，文字只負責解釋圖。

### 3.1 數量

- 每個單元至少 2 張圖：心智模型 SVG ＋ 一張範例、比較或流程圖。
- 每 300–400 字至少一個非文字元素：圖、表格、對照器、程式碼、互動示範。
- 有「改變參數會怎樣」的概念時，做互動示範（滑桿、按鈕）。
- 每課至少一個互動元素，讓讀者動手做一件事。
- 動畫只給真實機制（東西真的在移動或變化）；步驟、層級、比較用靜態圖。詳見 [build-and-widgets.md](build-and-widgets.md) 第 2.3 節。

### 3.2 概念 → 圖的類型

| 概念 | 圖 |
|---|---|
| 步驟、流程 | 流程圖（方框 ＋ 箭頭，標編號） |
| 循環、迴圈 | 環狀圖（靜態；只有真的在循環運作的機制才播放） |
| 兩種做法比較 | 左右對照或比較表 |
| 層級、包含關係 | 巢狀方框或樹狀圖 |
| 數量、比例 | 長條圖（不用圓餅圖） |
| 時間演進、版本變化 | 時間軸 |
| 系統組成 | 架構圖：中心元件 ＋ 周圍職責 |
| 輸入如何變成輸出 | 管線圖：輸入 → 處理 → 輸出 |
| 機率、選擇 | 分支圖，標上比例 |

### 3.3 SVG 寫法

- 用主題 class：`fill-ink`、`stroke-ink`、`fill-surface`、`fill-bg`；彩色底寫 `style="fill:var(--m5)"`，上面的文字加 class `on-color`。深淺色模式都要看過。
- `<svg role="img" aria-label="完整描述圖的內容">`；複雜的圖在圖說補一句重點結論。
- 圖裡文字在 375px 寬度縮放後仍要 ≥ 12px：viewBox 寬 700 時，字級至少 22；太擠就改成手機版直排的第二張圖。
- 顏色不是唯一的訊號：正確／錯誤、好／壞同時有文字或符號。
- 對比照 design-tokens.md 第 2 節：線條與方框 ≥ 3:1、文字 ≥ 4.5:1。
- 動態的圖可以逐步控制（上一步、播放／暫停、下一步、重設），reduced-motion 時不自動播放。
- 幾何：先定節點座標，再由節點算線段端點。每段線的兩端都接在方框邊緣、圓內、箭頭上，指向文字時停在文字前 6–10px；時間軸從第一個節點中心畫到最後一個節點中心；刻意不接的線加 `data-free-ends="原因"`。
- 文字：不跨在框線或圓的邊線上，在圖形內要留 4px 內距；和線段至少 3px；不重疊。SVG 的 `<text>` 不會自動換行，手動分行時每行至少 2 個字。先算寬度（中文約 1 倍字級、英數約 0.55 倍），放不下就分行、縮短文字或加大圖形，不縮字級。
- 每張圖畫完就跑 [layout-geometry.md](layout-geometry.md) 6.5 節的檢查腳本。

## 4. 時效與查證

### 4.1 研究階段

- 開工時寫下今天的日期，搜尋時把年份與月份放進關鍵字。
- 模型名稱、工具版本、指令、參數、價格、限制、統計數據，一律搜尋查證，不靠記憶。
- 優先順序：官方文件 → 官方部落格與 changelog → 標準組織 → 第三方文章。只有第三方來源的，標註「僅第三方來源」。
- `research-notes.md` 每一條寫：事實、來源 URL、查證日期、可信度（✅ 官方確認／🟡 摘要或間接／⚠️ 未確認）。
- 已經被取代的做法，不刪掉，改成「舊做法 → 現在的做法」區塊，寫出從哪一版開始變。

### 4.2 寫進課程時

- 每個指令、功能名稱都要能對應到 `research-notes.md` 的一條來源；對不到就不寫，或用 `unverified` 區塊標「⚠️ 截至 YYYY-MM 查證狀態：未確認」。
- 每個單元頁尾列出來源與查證日期。
- 全站頁尾寫「內容更新至 YYYY 年 MM 月」＋ 參考資料頁連結。
- 變動快的主題（AI 工具、框架版本、價格），在 `HANDOFF.md` 寫下次該重新查證的日期（建議 3 個月）。

## 5. 寫作

照個人溝通規範：
- 繁體中文、台灣用語；術語第一次出現寫「中文（English）」並包成 `[[術語]]`。
- 段落最多 3 句；一段最多一處粗體、一個破折號。
- 不用 AI 腔詞彙（值得注意的是、深入探討、至關重要、全方位、無縫、賦能、打造）。
- 不用 emoji 當項目符號；用文字貼紙標籤。
