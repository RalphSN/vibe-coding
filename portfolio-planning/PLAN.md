## 風格方向

- 參考 OZ 的特徵：白色無限空間、浮島、色彩分區、可愛化身、平塗色塊加清楚輪廓線。
- 精密度放在造型、輪廓、動態細節，不靠寫實貼圖與即時光影；這也是效能能兼顧的原因。
- 版權：只參考風格，不用 OZ 的 logo、角色（如 King Kazma）或介面原樣。

## 風格方向（D8 定案）

淺色（預設）用方向 1「白色數位雲」，深色模式用方向 3「夜間霓虹網格」；方向 2 不採用。

### 淺色與深色怎麼共存

| 項目 | 做法 |
|---|---|
| 場景 | 同一套模型與動線，只換色票、材質參數與背景 |
| 切換依據 | 預設跟隨系統 `prefers-color-scheme`，選單可手動切換並記住 |
| 色票 | 每座浮島的主色各定淺色、深色兩組（1-3 色彩分區時一起定） |
| 深色的光效 | 桌機高畫質才開 bloom；手機與中低畫質用自發光材質＋假光暈貼片，不開後製 |
| 輪廓線 | 淺色是深色線，深色改成發光細線 |
| 效能 | 深色模式不能另外加預算，一樣要符合 D7 |

風險：深色模式的 bloom 是手機發熱主因，垂直切片時兩種模式都要實機測。

### 三個候選的比較（保留作為決策紀錄）

三個都以 OZ 為起點，差在光線、材質與氣氛。

| 項目 | 1. 白色數位雲（推薦） | 2. 玩具模型箱 | 3. 夜間霓虹網格 |
|---|---|---|---|
| 一句話 | 白色無限空間裡漂浮的彩色幾何島 | 像桌上的精緻微縮模型，圓潤、有手感 | 深色宇宙裡發光線條構成的島 |
| 關鍵字 | 乾淨、明亮、平塗、輪廓線 | 圓角、黏土感、微縮、暖 | 發光、科技感、對比、夜晚 |
| 背景 | 純白到淡灰漸層，遠處有淡色網格 | 柔和米色或淡天藍，像攝影棚 | 深藍黑，星點與網格 |
| 材質 | toon（卡通著色）＋外輪廓線 | matcap 或預先烘焙的柔和陰影（baked AO） | 自發光材質＋光暈後製（bloom） |
| 精密度放在哪 | 造型輪廓、UI 細節、動態 | 模型倒角、小物件數量、陰影質感 | 線條動畫、光效、粒子 |
| 效能 | 最好：幾乎不用即時光影 | 中：烘焙貼圖吃記憶體（iOS 要注意） | 最差：bloom 在手機最耗電、最容易發熱 |
| 素材製作成本 | 低–中 | 高：每個物件都要精修模型 | 中 |
| 對求職的訊號 | 設計感、系統化、效能意識 | 美術與細節控 | 技術感、特效能力 |
| 主要風險 | 太像 OZ、或太素顯得空 | 製作量大，容易拖時程 | 「賽博龐克」很常見，難做出辨識度；手機發熱 |
| 深色模式 | 可做「夜晚版」：同場景換色票 | 可，但烘焙陰影要做兩套 | 本身就是深色，淺色版難做 |

### 推薦方向 1 的理由

1. 和效能預算（D7）最合，手機切 B 模式也撐得住。
2. 素材精密度靠造型與動態細節，不靠貼圖，製作量可控。
3. 可以借方向 3 做「夜晚版」當深色模式，同時展示主題切換能力。

### 不論選哪個，都要有自己的記號

避免「只是 OZ 的仿作」：加 1–2 個屬於你的視覺母題，例如程式碼括號 `{ }` 形狀的傳送門、作品卡像書背（呼應現有書櫃），或你的個人色。第 1-2「世界觀與命名」時一起定。

### 推薦方案 1 的理由

### 分區混搭（D9 定案，選項 A）

三個世界觀都用，各放在對應的區域。像 OZ 本身：一個世界、多個街區，各街區有自己的樣子。

| 選項 | 底層（大廳、UI、導覽、傳送門外框） | 各區 |
|---|---|---|
| A（推薦） | OZ 白色數位雲 | Runtime 雲、浮游書庫、訊號星圖各管一區 |
| B | Runtime 雲 | 其他區換主題 |

推薦 A：底層中性，三個主題放在一起才不會互相打架；底層用 Runtime 時，圖書館和訊號區會像「程式世界裡突然出現一座圖書館」。

#### 區域與主題對照（選項 A）

| 區域 | 主題 | 放什麼 | 為什麼這樣配 |
|---|---|---|---|
| 大廳 | OZ 白色數位雲 | 自我介紹、聯絡、履歷 | 中性的出生點，所有區從這裡出發 |
| 軟體工程區：網頁、遊戲、AI 實驗室 | Runtime 雲 | 前端網頁、前端遊戲、AI-coding 新作與前後對照 | 目標職缺的主力區 |
| 圖書館（新增） | 浮游書庫 | Vibe-Coding 書櫃、課程（著作）、文字書籍、讀書筆記 | 你本來就要做自己的圖書館；從 AI 實驗室移出書櫃與課程 |
| 案例區 | 訊號星圖 | 專案管理、行銷 | 行銷本身就是「發出訊號、看觸及」；觸及、轉換可以畫成訊號強度與星座連線 |
| 攝影區 | OZ 白色數位雲（展覽館） | 攝影作品 | 照片放在中性白牆最好看，主題太強會搶畫面 |

區域數從 6 個變成 7 個（多了圖書館）。

#### 讓混搭不變成拼湊的共用規則

| 共用（全世界一致） | 各區可以不同 |
|---|---|
| toon 著色＋輪廓線 | 道具與建築造型 |
| 化身（同一隻，進區可換配件） | 點綴色（主色仍依 1-3 色彩分區） |
| UI、字體、作品卡結構 | 傳送門形狀（`{ }`、書頁、天線） |
| 操控方式與相機規則 | 環境小動畫（程式碼粒子、飄落書頁、訊號波） |

#### 對成本與效能的影響

| 項目 | 影響 | 對策 |
|---|---|---|
| 素材量 | 增加：3 套主題道具 | 每區道具控制在 10–15 種，大量用 InstancedMesh 重複擺放 |
| 載入 | 增加 | 進區才載該區主題素材，離開卸載（原本就規劃分區延遲載入） |
| 深色模式 | 每個主題都要夜晚版 | 夜晚版只換色票與自發光參數，不做第二套模型 |
| 垂直切片 | 不變 | 第 4 階段只做大廳＋1 個 Runtime 島，驗證共用規則 |

## 區域結構（D9 定案，7 區）

依目標職缺排序，越前面越先被看到：

| 順序 | 區域 | 主題 | 顯示名稱（暫定） | 放什麼 | 呈現方式 |
|---|---|---|---|---|---|
| 0 | 大廳 | OZ 白色數位雲 | 大廳 Plaza | 自我介紹、聯絡方式、履歷下載 | 化身出生點，所有區從這裡出發 |
| 1 | 網頁島 | Runtime 雲 | `<web />` 網頁作品 | 前端網頁 | 浮空程式視窗，點開可直接互動或看影片 |
| 2 | 遊戲島 | Runtime 雲 | `gameLoop()` 遊戲作品 | 前端遊戲 | 街機台，能在頁面裡直接玩 |
| 3 | AI 實驗室 | Runtime 雲 | `/lab` AI 實驗室 | AI-coding 新作、舊作前後對照 | 持續施工中的島，附更新日誌 |
| 4 | 書庫 | 浮游書庫 | 書庫 Stacks | Vibe-Coding 書櫃、課程（著作）、文字書籍、讀書筆記 | 書架與書背，作品卡就是書 |
| 5 | 案例區 | 訊號星圖 | 訊號站 Signal | 專案管理、行銷 | 案例研究格式；觸及與轉換畫成訊號強度 |
| 6 | 攝影區 | OZ 白色數位雲 | 展覽館 Gallery | 攝影作品 | 白牆展覽館，點開看大圖 |

排序理由：前端、遊戲、AI 對應目標職缺放前面；圖書館的課程是 AI-coding 的實際產出，接在 AI 實驗室後面；案例與攝影補充產品思維和美感。順序可在第 1-5 動線草圖時再調。

傳送門依主題換形狀：Runtime 區 `{ }`、圖書館翻開的書頁、訊號站天線光束、OZ 區用中性圓環。

### 作品卡統一欄位

名稱、一句話、你的角色、技術、技術亮點、年份、連結（Demo／GitHub）、封面。

### 案例島的呈現格式

1. 問題：當時遇到什麼狀況
2. 角色：負責哪一塊
3. 做法：3 個關鍵動作
4. 結果：數字；不能公開時用比例或區間
5. 視覺：數據圖表、時間軸、流程圖

### 舊作前後對照

| 舊作類型 | 處理 |
|---|---|
| 真實客戶、有成果 | 放案例島 |
| 能代表成長的 1–2 個 | AI-coding 重做，前後滑桿對照，放 AI 實驗室 |
| 純練習、沒有故事 | 不放 |

## 互動模式細節

| 項目 | A 導覽模式 | B 自由模式 |
|---|---|---|
| 預設 | 是 | 按鈕切換 |
| 桌機操控 | 點擊浮島 | WASD＋拖曳轉視角 |
| 手機操控 | 點擊浮島 | 虛擬搖桿＋雙指轉視角 |
| 移動範圍 | 相機固定路徑 | 只在浮島表面；跨島用傳送門或自動飛行 |
| 碰撞 | 不需要 | 簡化形狀，不引入物理引擎 |

開發順序：垂直切片先做 A，確認效能後在第 5 階段加 B。操控層獨立，桌機與手機只差輸入來源。

隱藏成本：B 看得到浮島背面與邊緣，素材要做全身，不能只做相機看得到的面。

## 快速瀏覽（2D 版）

招募者常只花約 30 秒，履歷與作品清單要在 1 次點擊內看到。

| 項目 | 做法 |
|---|---|
| 入口 1 | 載入畫面同時給「進入世界」與「快速瀏覽」兩個按鈕，不必等 3D 載完 |
| 入口 2 | 3D 場景內右上角常駐「快速瀏覽」按鈕 |
| 自動導向 | 低階裝置、不支援 WebGL、開啟 `prefers-reduced-motion` 時預設進 2D |
| 內容 | 自我介紹、履歷下載、作品卡清單（依浮島分組、同樣順序）、聯絡方式 |
| 資料來源 | 和 3D 共用同一份作品資料，只維護一次 |
| SEO | 2D 版是可被搜尋引擎讀到的 HTML，分享連結預覽也用它 |
