# 程式碼品質

## 優先順序

專案現有的風格、lint 設定、命名慣例，優先於這份規範和個人偏好。

## 通用

- 命名寫出用途：`userCount` 而不是 `n`；布林值用 `is`、`has`、`can` 開頭。
- 函式名稱要能用一個動詞片語說完；需要用「和」「並且」才說得完，就拆成兩個函式。
- 函式超過 40 行先考慮拆分。
- 用提早 return 處理例外情況，巢狀不超過 3 層。
- 數字與字串常數抽成具名常數，`0`、`1`、`''` 除外。
- 不留被註解掉的程式碼、不留 `console.log` 除錯輸出。

## TypeScript

- `tsconfig` 開 `strict: true`。
- 不用 `any`；型別未知時用 `unknown` 加型別守衛（type guard）收斂。
- 不用 `@ts-ignore`；真的要壓錯誤時用 `@ts-expect-error` 並在同一行寫原因。
- 函式的參數與回傳值寫明型別；匯出的函式一定要寫。
- 用 `as` 斷言前先確認無法用型別守衛取代。

## 錯誤處理

- 不吞例外：`catch` 區塊至少要記錄錯誤或重新拋出，不能是空的。
- 錯誤訊息寫出「什麼失敗、用了什麼輸入」。
- 只在能處理的那一層 catch，其他層讓它往上拋。

## 相依套件

新增套件前，在計畫裡寫出這四項，等確認：
1. 為什麼需要
2. 不用套件或用替代方案的做法
3. 套件大小（bundlephobia 或安裝後的大小）
4. 維護狀態：最後發版日期、每週下載量

## 註解

- 註解寫「為什麼這樣做」，不寫「這行做了什麼」。
- 預設用繁體中文註解；專案已有英文註解慣例時跟隨專案。
- 有 workaround 或繞過 bug 時，註解附上 issue 連結或原因。
