# 測試與驗證

## 「完成」的定義

四項都通過才算完成：
1. 能跑：開發伺服器或程式能啟動，沒有執行期錯誤。
2. 測試通過：專案現有測試全部通過，新功能有對應測試。
3. 靜態檢查通過：lint 與型別檢查（例如 `vue-tsc --noEmit`、`tsc --noEmit`）沒有錯誤。
4. 手動驗證：這次改動影響到的每個使用者操作流程，各實際走一次。

有任何一項沒做，回報時寫明哪一項、為什麼；寫出跑了哪個指令和結果（通過幾個、失敗幾個）。

## 測試規則

- 不為了讓測試通過而修改或刪除測試；測試本身錯了，先回報再改。
- 修 bug 先寫一個能重現問題的失敗測試，再修程式碼讓它通過。
- 測試名稱寫出情境與預期結果，例如 `returns 0 when cart is empty`。
- 不在測試裡用 `.only` 或 `.skip` 後就提交。

## UI 改動

- 實際在瀏覽器或模擬器裡看過，附截圖或寫出看到什麼。
- 檢查主流裝置寬度：360、390、430、768、820、1024、1280、1366、1440、1920px；每種寬度都沒有水平捲軸，按鈕不被壓縮、元素不重疊。
- 頁面最上方與捲到最底各看一次：sticky／fixed 元素（頂部列、側欄、浮動按鈕）要對齊彼此，捲到底時不能蓋過頁尾。
- 「沒有溢出」不等於「有對齊」：相鄰的邊框、線條、文字要量位置，不只看有沒有超出畫面。
- 截圖失敗（例如視窗被隱藏）時，寫明「未截圖」與改用的檢查方式。
