# 原型轉正式

## 步驟

1. 盤點：列出檔案、相依套件、目前能跑的功能、已知問題。產出盤點清單給使用者確認範圍。
2. 開新分支：`refactor/productionize`。
3. 依下面的順序清理；每完成一項就 commit 一次，並確認程式還能跑。
4. 每項完成後在清單打勾回報；卡住的項目寫原因。
5. 最後跑 `verify-done` 的完整檢查。

## 清理順序

1. [ ] 確認能跑：先跑一次，記錄目前的行為當基準
2. [ ] 補主要流程的測試（先補測試再重構，才知道有沒有改壞）
3. [ ] 刪除沒用到的檔案、元件、匯出、相依套件
4. [ ] 型別：移除 `any`、`@ts-ignore`，開 `strict`
5. [ ] 抽出重複三次以上的程式碼
6. [ ] 補錯誤處理與載入狀態
7. [ ] 寫死的網址、金鑰、設定改成環境變數，補 `.env.example`
8. [ ] 安全檢查清單（輸入驗證、XSS、授權、相依套件漏洞）
9. [ ] lint 與 formatter 設定，修到 0 錯誤
10. [ ] README：用途、安裝、啟動、環境變數

## 規則

- 一次只做一項；不把重構和功能修改混在同一個 commit。
- 行為要和第 1 項記錄的基準一致；要改行為先問。
- 刪除檔案前列出清單等確認。
