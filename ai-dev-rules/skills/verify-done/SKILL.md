# 完成檢查

## 步驟

1. 從 `package.json` scripts、`Makefile`、README 或專案規則檔找出專案的 test、lint、typecheck、build 指令。找不到就問使用者，不要猜。
2. 依序執行，記錄每個指令的結果：
   - 型別檢查：例如 `npx vue-tsc --noEmit`、`npx tsc --noEmit`
   - lint：例如 `npm run lint`
   - 測試：例如 `npm test`
   - 建置：例如 `npm run build`
3. 手動驗證：這次改動影響到的每個使用者操作流程，各實際走一次。
   - UI 改動：在瀏覽器實際操作，看 375px 與 1280px 兩種寬度。
   - Unity：寫出在編輯器裡的測試步驟，請使用者執行。
4. 有失敗就修，修完從第 2 步重跑；同一項失敗兩次就停下來回報。
5. 用下面的格式回報。

## 回報格式

```
<一句話：全部通過 / 有 N 項沒過>

- [x] 型別檢查：`<指令>` → 0 錯誤
- [x] lint：`<指令>` → 通過
- [x] 測試：`<指令>` → 24 通過、0 失敗
- [ ] 手動驗證：未驗證，原因：<原因>

下一步：<一個動作>
```

## 規則

- 沒跑過的項目打 `[ ]`，寫原因；不寫「應該可以」。
- 不為了通過而修改或刪除測試。
- 指令輸出超過 30 行時，只貼失敗的部分與最後的摘要行。
