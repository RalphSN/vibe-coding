# 先計畫再動手

## 步驟

1. 讀相關程式碼：入口檔、會被改到的檔案、呼叫它們的地方、現有測試。
2. 用下面的範本寫計畫。
3. 停下來等使用者確認；沒確認前不改任何檔案。
4. 使用者修改計畫後，照新版做；實作中要偏離計畫，先回報。

## 計畫範本

```
目標：<一句話>

會改的檔案：
1. <路徑>：<改什麼>
2. ...

會新增的檔案：<路徑與用途，或「無」>
新增相依套件：<名稱、理由、大小，或「無」>

步驟：
1. ...

驗證方式：<要跑的指令、要手動檢查的畫面>
風險：<可能壞掉的地方，或「無」>
預估時間：約 N–M 分鐘

要你決定：<一個問題，或「無」>
```

## 規則

- 計畫裡的檔案路徑必須是實際讀過、確定存在的（新檔案除外）。
- 有兩種以上做法時，列出來並標明推薦哪一個、一句理由。
- 計畫控制在 30 行內；細節留到實作時再說。
