## A. 全站學習設計

### A-1 每個單元的固定結構

照 `course-web-neo-brutalism` 的 `content-rules.md`：3 件事 → 暖身回顧 → 比喻＋限制 → 心智模型 SVG → 正式定義 → 對照範例＋半成品 → 3 個常見錯誤 → 3 題練習（回想／應用／遷移）→ 三個重點 → 來源。

### A-2 全課主軸：一個請求的旅程

每一課都回到同一張圖，標出「這一課在旅程的哪一段」：

```
你的程式 ──請求──▶ API ──▶ 模型 ──▶ 回應 ──▶ 你的程式
  │  messages        │  token 計費     │ stop_reason   │ 驗證、工具、顯示
  └─ 工具結果、檢索資料、安全檢查 都在「你的程式」這一側
```

核心觀念：**模型只會讀文字、寫文字；其他所有事（記憶、執行工具、查資料、擋攻擊）都是你的程式做的。**

### A-3 與既有規範、既有課程的取捨

| 項目 | 規範／現況 | 採用 | 理由 |
|------|------|------|------|
| 程式語言 | — | **TypeScript（Node 22+）為主，cURL 為輔** | 使用者已有 TS 課；SDK 型別完整 |
| 廠商 | — | **Claude API 寫程式碼；OpenAI、Gemini 只做概念對照表** | 其他家價格與參數第三方來源互相矛盾，寫死會很快過時 |
| 範例模型 | — | 程式碼用 `claude-opus-5-5`；成本課拿 Sonnet 5.5、Haiku 5.5 做比較 | 照 claude-api skill 的預設 |
| temperature | 原大綱要教 | **改教「temperature 是什麼 → 為什麼 2026-10-21 起被拿掉 → 現在用什麼控制」** | API 新版本送出就 400 |
| 和 `ai-chat-prompt-agent-course` 重疊 | 那門課教「使用 AI 工具」 | 本課教「用 API 做出 AI 功能」；prompt 與 agent 只講工程面，基本功連到那門課 | 不重複 |
| 真的呼叫 API | — | **不在網頁裡放 API 金鑰、不真的打 API**；互動元件用預錄的回應與模擬器 | 金鑰不能進前端；書櫃是靜態網站 |
| 每課長度 | 6–12 分鐘 | 8–12 分鐘 | 工程內容需要程式碼 |
| 外部套件 | Google Fonts、cdnjs | highlight.js（typescript、json、bash） | 程式碼上色 |

## B. 模組與單元

格式：`ID 標題（| 為斷點）`：目標。圖 1／圖 2。互動

### 模組 0　開始之前（`--m0`）
- **0-1 AI 應用工程|在做什麼**：分清「模型」「API」「應用」三層；本書在系列裡的位置。圖：三層架構；七本書地圖。互動：sorter（這件事是誰做的）
- **0-2 準備環境：|金鑰、SDK、|第一次呼叫**：API 金鑰放環境變數、裝 `@anthropic-ai/sdk`、跑出第一個回應；金鑰為什麼不能進前端。圖：金鑰流向（後端代理）；第一次呼叫的終端機畫面。互動：checklist

### 模組 1　LLM API 基礎（`--m1`）
- **1-1 一次 API 呼叫|的解剖**：端點、標頭、請求 JSON、回應 JSON 各欄位。圖：請求／回應對照；HTTP 往返。互動：reqbuilder
- **1-2 messages|與三種角色**：system、user、assistant；API 沒有記憶，歷史要自己帶；輪流規則。圖：對話陣列逐輪長大；「模型看到的全部」。互動：reqbuilder（組一段多輪對話）
- **1-3 控制輸出：|max_tokens、|stop_reason、effort**：temperature 的原理與退場、`effort`、`stop_reason` 五種值與該怎麼處理。圖：stop_reason 決策樹；temperature 對機率分布的影響（靜態對照）。互動：reqbuilder（送 temperature 看 400）
- **1-4 token：|模型的計量單位**：什麼是 token、中文與英文差多少、tokenizer 依模型不同、`count_tokens`。圖：同一句話的切法；中英 token 比較長條圖。互動：tokenmeter
- **1-5 計費、速率限制|與重試**：輸入／輸出分開算、算一次對話的錢、429 與 529、SDK 自動重試、指數退避。圖：多輪對話的累積成本；重試時間軸。互動：costcalc

### 模組 2　串流回應與前端 UI（`--m2`）
- **2-1 為什麼要串流：|等待的體感**：TTFT（第一個字出現的時間）vs 總時間；什麼時候不需要串流。圖：串流與一次回傳的時間軸對照；體感延遲。互動：ssestream（同一段回應兩種模式並排）
- **2-2 SSE：|一行一行的事件**：`event:`、`data:`、空行；Claude 的事件順序；`ping`。圖：SSE 原始文字解剖；事件順序圖。互動：ssestream（顯示原始行）
- **2-3 前端逐字顯示：|後端代理|與 ReadableStream**：EventSource 不能 POST；後端用 SDK 串流、轉送給前端；前端用 `fetch` 讀 stream；React 狀態更新。圖：瀏覽器－後端－API 三段；文字累加與重繪。互動：ssestream（切換「直接 append」與「批次更新」）
- **2-4 中斷生成、|斷線與錯誤**：AbortController、停止按鈕、部分輸出要不要存、串流中途錯誤、已產生的 token 照算。圖：中斷的訊號流向；錯誤處理狀態機。互動：ssestream（按停止、模擬斷線）

### 模組 3　Prompt 工程與結構化輸出（`--m3`）
- **3-1 系統 prompt|的結構**：角色、任務、背景與目的、限制、輸出格式；寫給新模型不要用吼的。圖：系統 prompt 的五個區塊；好壞對照。互動：sorter（把句子分到五個區塊）
- **3-2 範例、XML 標籤|與資料隔離**：少樣本範例、用標籤把資料和指示分開（也是防 injection 的第一步）。圖：有／無標籤時模型看到的邊界；範例數量與一致性。互動：切換對照（有無範例的輸出）
- **3-3 讓模型思考：|effort 與|思考區塊**：adaptive thinking、effort 五級、display 選項、什麼時候值得多花錢。圖：effort 與成本、品質的關係（示意）；思考區塊在回應中的位置。互動：拉桿（effort → 預估 token 與等待時間，標示為示意）
- **3-4 結構化輸出：|JSON Schema**：為什麼不要用 regex 撈 JSON、`output_config.format`、zod、`messages.parse()`。圖：自由文字 vs schema 約束；schema 與 TS 型別對應。互動：schemacheck
- **3-5 驗證、重試|與失敗處理**：`parsed_output` 為 null、`max_tokens` 截斷、`refusal`、重試策略、什麼時候該讓人工接手。圖：處理流程；失敗類型表。互動：schemacheck（注入各種失敗）

### 模組 4　Tool use／function calling（`--m4`）
- **4-1 工具是什麼：|模型只出主意**：模型不執行程式，只回傳「想呼叫什麼、帶什麼參數」；用戶端工具 vs 伺服器端工具。圖：誰執行什麼的分工圖；一次工具呼叫的訊息流。互動：sorter（這一步誰做）
- **4-2 定義工具：|名稱、描述、schema**：description 怎麼寫、參數 schema、`strict: true`、`tool_choice` 只用 auto 的原因。圖：工具定義解剖；好壞描述對照。互動：reqbuilder（工具定義版）
- **4-3 工具迴圈：|tool_use|到 tool_result**：迴圈怎麼寫、`tool_use_id` 對應、平行呼叫放同一則訊息、`is_error`、何時停。圖：迴圈流程；訊息陣列逐步長大。互動：toolloop
- **4-4 工具設計原則|與安全**：粒度、回傳內容要精簡、權限最小化、有副作用的工具要人工確認、Tool Runner。圖：工具風險分級；確認閘門。互動：sorter（哪些工具要確認）

### 模組 5　Embedding 與向量搜尋（`--m5`）
- **5-1 Embedding：|把意思變成座標**：向量是什麼、意思相近位置相近；和聊天模型的差別；Anthropic 為什麼不做 embedding。圖：文字→向量→平面；同義句聚在一起。互動：vecplot
- **5-2 相似度：|cosine 與點積**：角度 vs 距離、正規化後點積＝cosine（→ 隨身卷 1）。圖：兩個向量的夾角；三種度量排序比較。互動：vecplot（拖向量看 cosine）
- **5-3 向量搜尋|與向量資料庫**：暴力比對、近似最近鄰（HNSW 直覺）、pgvector 與專用資料庫、metadata 過濾。圖：暴力法 vs 分層圖；查詢流程。互動：vecplot（top-k 與過濾）
- **5-4 選 embedding 模型：|維度、query/document、成本**：`input_type`、維度截斷、量化、換模型要全部重算。圖：維度與儲存成本；query／document 前綴。互動：costcalc（儲存量計算版）

### 模組 6　RAG：切塊、檢索、引用（`--m6`）
- **6-1 RAG 的兩個階段：|索引與查詢**：為什麼需要 RAG（模型不知道你的資料、會過時）、整條流程。圖：索引期與查詢期；沒有 RAG 時的幻覺。互動：ragtrace
- **6-2 切塊：|大小、重疊、|依結構切**：太大太小各有什麼問題、重疊、照標題切、表格與程式碼。圖：同一篇文章三種切法；答案被切斷的情形。互動：chunker
- **6-3 檢索品質：|混合搜尋、rerank、|脈絡化切塊**：BM25＋向量、reranker、Contextual Retrieval 的數字。圖：各方法失敗率長條圖；兩段式檢索。互動：ragtrace（開關各種方法）
- **6-4 生成與引用：|讓答案有出處**：把檢索結果放進 prompt 的格式、citations 功能、「找不到就說不知道」。圖：prompt 組裝；引用對應原文。互動：ragtrace（看引用指回哪一段）
- **6-5 什麼時候|不需要 RAG**：1M context 直接塞、prompt 快取、成本與延遲比較、決策表。圖：決策樹；三種做法的成本比較。互動：costcalc（RAG vs 長 context）

### 模組 7　Agent 與 MCP（`--m7`）
- **7-1 workflow 與 agent：|誰決定下一步**：程式決定 vs 模型決定、四個檢查（複雜度、價值、能力、錯誤代價）。圖：控制權光譜；四項檢查。互動：sorter
- **7-2 Agent 迴圈：|觀察、行動、停止**：迴圈本質就是 4-3 的工具迴圈；停止條件、步數與 token 預算、context 變長的處理。圖：迴圈與預算；context 成長曲線。互動：toolloop（多步任務版）
- **7-3 五種常見模式**：鏈、路由、平行、協調者－工人、評估者－優化者；各自適合什麼。圖：五種模式靜態圖；選擇表。互動：sorter（情境配模式）
- **7-4 MCP：|工具的通用插頭**：沒有 MCP 時每個應用都要自己接每個工具；host、client、server；tools、resources、prompts 三種元件與誰控制。圖：N×M 對照 N+M；三種元件控制權。互動：切換對照（有／無 MCP）
- **7-5 MCP 的傳輸|與 2026-07-28 規格**：stdio 與 Streamable HTTP、JSON-RPC、無狀態設計、取消；舊教學裡的 initialize 是什麼；安全（只裝信任的伺服器）。圖：兩種傳輸；新舊規格對照。互動：sorter（stdio 還是 HTTP）

### 模組 8　上線現實（`--m8`）
- **8-1 評估：|沒有量就沒有改進**：建測資、評分方式（精確、規則、LLM 裁判、人工）、改 prompt 前後比較、測試集不能拿來調。圖：eval 迴圈；評分方式比較。互動：evalgrid
- **8-2 成本：|先拿免費的**：快取（前綴規則與價格）、批次 5 折、精簡輸入、effort、換模型、看「每完成一件事」的成本。圖：槓桿順序；快取命中前後成本。互動：costcalc（完整版）
- **8-3 延遲：|使用者等多久**：TTFT、串流、平行、快取、較小模型、Fast mode。圖：延遲組成長條；平行 vs 串行時間軸。互動：拉桿（各項優化對延遲的影響，示意）
- **8-4 Prompt injection：|攻擊從哪裡來**：直接與間接、資料裡的指令、致命三角、為什麼沒有完美防護。圖：攻擊路徑；致命三角。互動：sorter（直接／間接／不是攻擊）
- **8-5 防護與上線清單|＋總複習**：分層防護（隔離資料、最小權限、人工確認、輸出處理、監控）、上線檢查清單、15 題總複習。圖：分層防護；上線前流程。互動：checklist
